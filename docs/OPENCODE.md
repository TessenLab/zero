# ZERO in OpenCode

**OpenCode is the first distribution focus for Project Zero Alpha.**

The objective is not to make developers learn a new editor before they can try ZERO. Project Zero should meet developers inside an agentic coding workflow they already understand.

## ZERO

The canonical developer-facing model reference is:

```text
tessen/project-zero
```

That identity is intentionally stable. Tessen can evolve eligible routing behind the Gateway without changing what developers select.

## The Alpha experience

The intended experience is deliberately short:

```text
OPEN OPENCODE
      ↓
AUTHENTICATE WITH TESSEN
      ↓
SELECT tessen/project-zero
      ↓
POINT ZERO AT A REAL REPOSITORY
      ↓
BUILD
```

The Alpha proposition is:

> **Free coding intelligence. 100T shared tokens every day.**

The daily Zero Pool is planned to reset at **00:00 UTC**. Access remains metered and subject to fair-use, capacity, reliability and abuse controls.

## Why OpenCode first

Distribution matters as much as the model experience.

Instead of asking developers to migrate their coding workflow to a new Tessen editor, ZERO starts by fitting into an existing agentic coding environment.

The launch test is therefore not "does the documentation look complete?"

It is:

> Can a new developer discover ZERO, authenticate, select `tessen/project-zero`, and complete a useful real coding task with minimal friction?

## Discovery goal

The strongest version of the Project Zero launch is one where ZERO is easy for existing OpenCode developers to discover and select.

Tessen will pursue the legitimate integration and discovery paths available to make that experience as direct as possible.

This document does **not** claim that ZERO already has native or default OpenCode distribution. We will update it when that status is real.
